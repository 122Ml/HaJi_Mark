# 本地自动演示

原生 Windows 悬浮控制器独立于网站运行，打开真实 Edge 浏览器。教师与学生使用隔离的浏览器会话，业务写入由现有页面完成；HTTP 查询和 PostgreSQL 只读计数用于核对结果。不会向产品页面注入菜单、演示数据接口或模拟模型响应。

## 启动与控制

先启动本地 Docker 平台与 RAG worker，在仓库运行：

```powershell
.\scripts\start-auto-demo.ps1
```

本机地址为 `http://127.0.0.1:18080`，账号沿用本地人工验收配置。需要 Python（含 Tkinter）、Node、Playwright 和 Edge；入口查找项目依赖与 Codex 桌面运行时内的 Playwright。

| 操作 | 行为 |
| --- | --- |
| Ctrl + Alt + D | 展开／收起控制器；被占用时尝试 Ctrl + Alt + Shift + D，以窗口显示为准 |
| 演示所选／连续演示 | 执行所选流程及尚未完成的前置流程，或依次执行全部流程 |
| 暂停／接管 | 当前操作收尾后暂停后续操作，可手动操作浏览器；后台任务继续 |
| 继续演示 | 从后续操作继续；若人工接管后对象状态不匹配，停止并保留回执 |
| 停止 | 阻止后续操作；已提交请求和后台任务保留 |
| 浏览器 | 打开或切回真实浏览器 |
| 新批次 | 确认后新建独立课程，重新执行写入和模型调用；旧批次不删除 |
| 记录 | 打开本批次回执、日志、截图及 CSV 目录 |

播放时主窗口收为小进度窗，可随时展开。关闭主窗口仅隐藏；使用“退出”结束控制器和浏览器。快捷键注册均失败时仍可从任务栏找到窗口。

## 演示内容

课程主题为**数据库系统原理**。`scripts/auto-demo/course.md` 是自编的事务、并发控制与恢复讲义，包含时序、隔离级别表、锁与死锁、WAL、索引及练习；`agent-material.md` 是导入助理使用的补充资料。

| 流程 | 可见操作与持久结果 |
| --- | --- |
| 课程与教学组织 | 创建课程，维护六章和知识点，加入学生，发布课程 |
| 资料导入、解析与发布 | 文件上传、真实解析、核对片段、发布学习资料、Embedding 建索引 |
| 知识提炼与审核入库 | 选择原文、真实模型提炼、编辑用途与关联、确认并更新索引；另建明确标注的教师自编锁实验示例 |
| AI 出题与评分标准确认 | 检索并选依据，生成题目／参考解答／标准草稿，分别确认 |
| 作业与客观测验发布 | 作业固定引用题目及标准版本；发布独立单选测验 |
| 学生学习、笔记与作答 | 阅读、笔记、收藏，保存草稿、正式提交，真实客观规则判分 |
| AI 评阅、复核与正式反馈 | 生成逐点草稿，教师确认发布，学生查看，下载正式 CSV |
| 资料问答与学习路径 | 检索问答与引用历史，生成规则路径，真实 AI 排序，保存偏好 |
| 共性诊断与干预复查 | 分析同题同标准正式失分作答，确认标签，下发补学，核对下发后新证据，复查完成 |
| 对话助理导入附件 | 私有附件、自然语言协调、问题卡、导入审批，等待解析并核对原件 |
| 内容变更与整组重评 | 新建相同满分标准，关闭作业，冻结有效提交，逐份复核并统一发布，保留旧结果 |
| 课程互动与教研记录 | 公告、学生提问、教师回复，保存教研及课程能力关联记录 |

学生答案为脚本预设教学作答。教师确认／发布是专用演示课程内获授权的脚本操作，不代表独立人工审核、真实班级共性结论或教学效果评测。资料与教研内容均为自编，不冒充学校课程原件、真实学生成绩或网络调研结果。

## 重复播放与失败处理

状态位于忽略目录 `.local/auto-demo/state.json`，每批另存独立目录。写入记录真实请求是否发出、HTTP 状态和对象／任务 ID；完成流程另存截图及数据库计数。完整回执保存在本机，控制窗只接收简要进度。

- 完成流程再次选择时展示已保存页面，不重复创建对象或收费。重演输入至落库全过程时选择“新批次”。
- 已完成依赖复用其对象；执行第七条不必重新上传前六条的内容。
- 已提交但未收到明确结果的写请求标记 `unknown`，阻止自动重发，先核对真实对象。
- 失败任务保留；确认重试后才另发明确失败的模型任务。成功、运行中和结果未知的调用不自动重试。
- 助理出现计划外输入或审批时停止，保留问题卡，不批准未预设操作。
- 收费调用共用已有的 50 元数据库预算；新批次不能重置预算。

知识提炼让模型选择 `evidence_fragment_ids`，服务端直接附上所选片段原文并执行来源／许可核对。模型不负责重新抄写引用，教师仍须判断提炼内容是否受到依据支持。无效输出保留原稿，事务不写入候选。

AI评阅只要求逐点给分，总分由服务端相加，再校验每点分值、引用、评分点完整性与教师审核状态。若模型仍返回总分，另存为`model_reported_score`供追溯，不用它决定正式得分。评分仍先存草稿，经教师确认后才能发布。

问题诊断让模型选择服务端切分的作答片段`evidence_ids`，由服务端还原不可变原句并核对所属提交；同一诊断项不重复计人，空白或不足证据明确列为未归类。模型改写引用、越界ID或重复计人均失败，保留原稿等待显式处理。

## 验证入口

```powershell
.\scripts\start-auto-demo.ps1 -Check
node --test scripts/auto-demo/core.test.cjs
node scripts/auto-demo/runner.cjs --headless --flow course
```

后两条需要已配置 Playwright 的 `NODE_PATH`，启动脚本会自动配置自身子进程。CLI 的 `--flow <id>` 逐条验收，`--new` 明确新建批次，`--retry-failed` 明确允许重试终态失败模型任务。流程标识与依赖以 `scripts/auto-demo/flows.json` 为准。

控制测试覆盖依赖顺序、暂停／继续、停止、在途成功回执保存、未知写请求禁止重放。测试对象不替代真实浏览器业务验收。真实通过情况以本批次 `state.json` 的 `flows`、`events.jsonl` 与数据库结果为准；失败日志保留。
