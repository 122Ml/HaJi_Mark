# 每周迭代与开工任务

每轮7天、每周课堂汇报一次；具体课堂日期未提供，因此不用虚构截止日期。S0 为当前初始化，后续S1起按实际课程周排定。计划不是已完成功能，教师追加必做项时优先重新排序。

2026-10-28 增补：参考平台前端 26 路由与浏览器本地闭环已完成，详见 [复刻验收](research/frontend-rebuild.md)。这提供了 S1 的交互基线，但不将 PL/CO/AS/GR/IN 的服务端授权、数据库保存和证据验收卡提前标为完成；成员从本地演示替换为真实接口时继续按下列 DoD 验收。

## 每周节奏

第1天：15—20分钟计划会，每人只领一个主要纵切面，明确下游等待的字段；葛炫毅记录不确定项。第2—4天：小提交＋Draft PR，每天文字更新“完成/下一步/阻塞”，阻塞超过一天找李然缩小或拆卡。第5天：先合最小依赖，串联同一名模拟学生；不等四人末日一次合并。第6天：补异常、数据留存和跨角色自测。第7天：课堂演示、反馈与10分钟回顾，更新下一轮卡。

汇报只需：本周目标、同一用户的真实演示、证据与失败用例、未完成/原因、下周一条目标。每人至少解释自己的输入输出，不把AI生成的说明当作自己已理解。

## Ready / Done

Ready：真实用户行为、输入输出样例、归属模块、验收步骤、必要依赖和责任人齐全。外部未就绪要标明，不让成员猜接口。

Done：页面→API→事务/查询→数据库真实连通；正常与关键异常自测通过；重新打开页面数据仍在；本模块越权检查通过；文档/契约同步；PR由李然审核、必需检查通过；周演示能复现。单纯前端fixture、接口永远200、AI自评分或未运行命令均不能当完成。
