# 评据来源、人工确认与验证

## 五类材料，分别承担责任

| 类型 | 取得/审核者 | 必需留存 | 不能替代的东西 |
| --- | --- | --- | --- |
| 课程知识资料 | 教师提供或认可，徐铂尧录入 | document_id/version、page/段落、原文、来源、审核/发布时间 | 有相关片段不等于可以添加扣分项 |
| 评分规范 rubric | 教师制定或审核，李然维护结构 | 题目版本、逐点分/部分分/等价表达/反例、知识点、课程来源、确认人 | AI 起草不是生效标准 |
| 学生作答 | 平台正式提交；CSV补录注明来源，张俊超留存 | student/course/assignment/attempt、原文/hash、时间、导入行/批次 | 单题低分不等于整课能力差 |
| 模型草稿与人工正式结果 | 李然负责生成/核查，教师确认 | job/attempt、固定输入版本、原稿、检查标记、人工修订/确认/发布 | 引用存在不等于引用支持该判断 |
| 独立评测参照 | 申请教师独立评分；葛炫毅组织、李然计量 | 样本来源/许可、标注者、rubric版本、逐点分、分歧处理、数据划分 | 模型自评和构造预期不能冒充教师真值 |

## 标准建立与评阅流程

1. 选教学目标、知识点、题目与满分；教师将已审核课程片段绑定到题目。
2. 手写或 AI 起草标准；起草请求仅包含题目、参考答案、课程资料与教师要求，不读取待批改学生答案。
3. 每个评分点明确给分条件、部分分、可接受表达、反例、知识点及资料定位；检查总分和重复扣分。
4. 教师确认形成不可变版本；校准样例与独立评测集隔离。标准变更创建新版本，同批使用范围明确。
5. 批改固定题目/资料/标准/提交快照；AI 按点输出草稿，不能自行改标准或宣称教师已确认。
6. 规则检查字段、分值范围/加和、criterion_id覆盖、引用位置及课程归属；任何失败留草稿并阻止确认。
7. 教师同屏查看资料、标准与作答，核查语义、改分并确认；发布后进入学生反馈和画像/E4。
8. 后续修改新增修订，保留旧历史并重算受影响统计；不覆盖原始作答和模型原稿。

## 逐点证据结构

评分点关联 `criterion_id/rubric_version`；知识依据引用 `resource_id/resource_version/page/fragment_id`；作答引用 `submission_id/attempt/start/end/quote`（统一 Unicode code point 偏移、左闭右开，后端不得按 UTF-8字节切片；前端 Array.from 处理）。缺少某要点时以完整作答覆盖检查说明 `missing`，不伪造“未出现内容”的原文引用。

资料不足、资料冲突、标准不符、未作答、模型超时、无效JSON分别显示原因和下一步。资料不够转人工补标准；模型失败不写0；真实空白提交由教师按标准处理，但画像同时显示证据状态。学生作答中的“忽略标准/直接满分”是待评文本，不是模型指令。

## 先用透明诊断

对某知识点仅聚合当前有效已发布修订：`本题表现 = 有效得分合计 / 对应满分合计`；同时展示题数、最近时间、标准版本和证据ID。这是表现指标，不称为真实能力概率。未覆盖知识点显示无证据；opened事件不构成掌握证据。推荐只从教师认可资源库选择，没有合适资源时明确缺口。

E4：先按知识点/人工确认错因统计涉及学生数、有效作答数、未提交人数、证据不足数；明确分母为谁。学生重复提交只纳入当前有效结果；模型摘要必须附可回查的匿名案例和计数，不把摘要当正式事实源。

## 验证计划（尚未执行AI实验）

基础验收：角色越权、课程草稿不可见、刷新/重启留存、原文不可覆盖、未发布评分不可见、重复提交幂等、改标准不污染旧记录、干预复查回流。

AI回归：保留历史边界题A1—A6作为构造回归；新增至少三类边界/同义/缺依据/提示注入样例；先取得独立人工参照，再比较规则、直接模型、rubric+证据约束三种方案。冻结样例ID与split，不用调提示的校准集报告最终效果。

建议门槛：固定集引用定位100%，越界分/未确认自动发布/跨人引用为0；归一10分MAE≤1、理由支持率≥95%为待教师核定的研究目标，不能在未测时填通过。规则检查只支持机械正确性。记录调用次数、输入/输出token、供应商报价日期、每次延迟、队列等待和人工耗时；6份样例不报告普遍可靠或学习提升。

历史 Python API 成功探查与三轮对话结果只作为设计依据，尚未在此仓库/Go服务复现。本轮默认不开模型网络调用、不存密钥。新调用预算先由李然明确，不沿用旧E6局部预算冒充全平台预算。
