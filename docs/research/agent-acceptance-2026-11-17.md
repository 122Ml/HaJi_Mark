# 对话助理本地验收：2026-11-17

本轮仅本地，基于真实 PostgreSQL、Redis、Worker、授权业务接口和服务端模型配置实施。公网没有更新。所有验收课程和学生作答均为有标签的教学构造数据，不涉及真实学生成绩。自动化脚本扮演用户回答问题及批准操作，用于验证交互协议和状态转换，不代表独立教师语义审核。

## 实施范围

协调 Agent 单层顺序委派资料知识、题目标准、作业评阅、学习支持专家。类型化业务工具复用原授权处理器；没有任意 SQL、shell 或任意 HTTP 执行器。对话、附件、运行、步骤、问题、审批和事件持久化；前端使用 Ant Design 问题卡／审批卡、执行记录、业务 SSE 和查询兜底。

`read-only` 禁写；`auto-review` 是确定性风险门禁，重要修改升级人工批准；`full-access` 仍要求正式确认和发布审批。读取作答／学情后持久限制同一会话的出题／标准能力。未知写入不自动重放；未知收费调用不自动重发。

## 实测发现与修正

- 知识候选虚构关联 ID：收紧生成上下文，限定真实知识点 ID，空关联使用空数组；保留原校验。
- 可选字段 null：仅删除已知可选空字段再校验；必填空值和未知字段继续失败。
- 原件、任务、知识点与依据 ID 混用：补强工具描述、模型上下文及真实任务回执；不放宽业务归属检查。
- 用复制正文代替原片段发布：明确来源许可链，复用已有草稿并走 source_publish；不制造可见权限。
- 协调者把作业错派给出题专家：固定领域关系，查询交专家，错误审批由验收白名单拦下，取消失败运行；无关草稿保留。
- 完整出题加三次确认触发初始16次模型调用上限：按实测改为32次，仍限制48次工具操作并保存检查点。
- 生成评分标准偏离给定部分分规则：原标准保留，额外验证教师给定规则通过新标准版本纠正的业务路径；不宣称模型自动保证标准语义正确。
- 纠正规则时协调者摘要遗漏完整 criteria，专家重新编写：审批前精确对照拦下，运行取消；运行时改为原样附上用户本轮请求，增加不继承旧轮／其他专家回执的回归用例。
- 仅传原请求导致已回答的问题再次出现：委派同时带上本轮已验证的输入卡回答，补充对应回归；真实浏览器断言同次导入只生成一张输入卡。
- 已答问题刷新后没有显示回答：返回持久 response 并回填表单；窄屏截图补等待侧栏隐藏及输入框边界断言。
- 浏览器复跑使用相同正文触发原有哈希去重，并非解析成功：保留409和原件，样本正文加入唯一验收标记再验证新导入，没有删除旧原件或绕过去重。
- 学生先检索后自行组织答复，没有走受引用校验的问答端点：严格验收未通过；明确学习专家默认调用course_answer，显式新运行后通过真实引用核对，保留前次尝试。
- 浏览器选择器误匹配历史“新对话”和多条助理消息、直接点击Ant Design只读输入被标签遮挡：限定创建按钮、等待首条消息并复用已有Select容器交互，不改产品绕过断言；失败报告归档。
- 助理Markdown继承pre-wrap，结构换行产生大段空白：仅在消息正文覆盖white-space，补充计算样式断言；重新Docker构建并目视核对师生截图。

失败、重试、恢复和预算均保存在忽略的 `.local/agent-acceptance.json` 及对应日志，没有清空预算或删除失败记录。迁移前数据库备份在 `.local/backups/`，已核对备份目录，未做本轮完整恢复演练。

## 验收边界

模型调用采用完整 assistant／tool 消息协议，当前为供应商非流式调用；SSE 是应用业务事件，不能称为 token 流。四专家使用同一可选择的服务端生成配置，不代表四个独立训练模型。

集成测试覆盖越权、CSRF、审批快照变化、只读、取消、恢复、未知写入、任务等待和学习数据隔离；真实模型只验证选定业务主线，没有逐工具覆盖所有变体。整卷候选采纳、学生正式交作业等仍可使用既有业务页面，不声称全站操作全部可对话代办。未做大规模并发、安全审计、模型准确率评测或教学效果研究。
