# 前后端工作区协同修正记录

日期：2026-11-19。对应[业务链审计 F01—F16](frontend-business-chain-audit-2026-11-18.md)。本记录维护实施与实际验收证据；旧审计保留为改动前的事实。

## 目标与边界

本轮改动活动应用 `web/src/live`，沿认证／课程授权 → learning API → PostgreSQL／后台任务 → 对象回执补齐操作链。Agent继续使用授权Gateway和原业务状态机；不跳过教师确认、发布、冻结版本或学生数据隔离。

1. 修正同页操作与上下文交接 → 核对真实业务对象和数据库回执。
2. 核验权限与状态转换 → 在私有schema中运行后端集成回归，不调用付费模型。
3. 构建真实API、worker、web并做师生浏览器回归 → 检查交互、刷新恢复、局部失败与移动宽度。
4. 更新155条API入口清单及工作区导航 → 运行文档、差异和catalog检查。

## 验证范围与证据

- TypeScript `tsc --noEmit`、API／worker／web的Docker构建通过；活动前端静态检查另核对真实导入图、组件使用、未使用声明。
- Docker私有schema回归使用真实PostgreSQL、真实HTTP处理器及构造提供商；不是实际模型效果或教师验收。
- 隔离浏览器环境使用独立Compose项目 `hajimark-frontend-check`、本机18082端口和本机18083构造提供商；不挂载真实模型密钥，不改18080已有课程，不访问生产。
- API清单仍为155个method＋path；这是源码入口盘点，不能等同于155个接口都完成了动态验收。
- 最终浏览器结果、构建日志和私有测试数据保存在忽略目录 `.local/frontend-integration-2026-11-19/`。
- 最终六阶段共23组浏览器断言通过；记录中的pageerror与未注入的API 5xx均为零。教师18、学生11个路由的读取另检查4xx／5xx。TypeScript、活动前端静态检查、文档检查、git diff --check及工作区catalog检查均通过；catalog仍只证明元数据，不构成生产发布验收。

## 纵向业务核对结果

1. **教师资料入库**：手工新建或多文件导入→当前对象回执→真实解析／索引任务→原文核对→选择知识点和片段发布→原位提炼候选→编辑用途与可见性→确认知识。学生只读发布文本和已确认开放知识；未选私有片段不进入当前资料检索。
2. **备课到正式诊断**：作业草稿→选题器内核对题目、参考解答、标准→返回保存固定版本→发布→学生提交→教师正式评分→共性诊断草稿→教师确认→按具体学生作答建干预草稿→单独下发。浏览器脚本通过授权API准备带标签的学生作答与4分正式结果，其余关键新工作区操作由UI完成。
3. **内容修订到重评**：原件新版本→引用影响中的具体作业题→原位重评抽屉→选择统一新标准→预览→冻结名单→逐点评分和确认→整组发布→学生看到8分及原4分历史。正式证据变化后旧诊断失效，不能继续安排新任务；保存内容处理决定是独立动作。
4. **对象内助理与交流**：在资料内打开助理→附服务端授权引用→构造提供商驱动真实工具建草稿→结构化对象回执→回到业务对象；不同对象会话与未发草稿分开。同一讨论下发布回复并核对真实父帖，不跳页首编辑。

复测实际修正了两个额外断点：同题干跨作业的诊断选项无法区分（补所属作业），以及快速提炼结束后候选面板沿用30秒空缓存（打开面板强制重读）。还去除了当前原件外层及候选区重复任务面板，限制左侧原件列表高度以保持对象工作区可操作。
