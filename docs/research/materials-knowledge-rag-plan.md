# 学习资料与知识库：RAG 开工方案

2026-11-11。本文保留开工时的目标方案和待评测项；下文“当时现状/待实现”不能作为当前状态。当前实现以[架构](../architecture.md#资料与知识库)、[接口](../contracts.md#2026-11-11-资料知识与模型任务)和[验收记录](../verification.md)为准。用户随后提供新凭据并启动Docker，本地真实链路已进入实施和验收。

本轮已交付原件/学习资料/精炼知识的独立版本与权限、原文直接索引、中文混合检索、真实模型草稿及教师确认链。下文的完整目标中，PDF精确坐标、复杂表格专用切分、30查询质量基准、来源变更影响清单及定向重评界面仍未实现；现有位置为页/幻灯片/内容块，不保证版式或公式语义。当前worker串行执行，不采用方案中的两路生成并发；调用失败由用户显式重试，未知计费保守留账。候选写入与提炼任务完成同事务提交，重复投递不会再次写入已完成候选；整个异步系统不承诺严格exactly-once或供应商侧调用去重。生产OCR资源峰值和真实账单尚未核对，公网未更新。

同日自检补齐了完整原件发布集合校验、重新解析失败保留旧原文、知识审核的编辑版本锁、事务内索引请求、取消任务最终写入检查，以及草稿任务刷新恢复和冻结依据展示。问答正文标记须与已核对引文对应。旧确认知识版本目前保留为独立条目，确认新版本不会自动归档旧版本；替代旧内容时需教师明确归档，自动版本淘汰和影响清单不在当前实现内。

- 活动实现为 `web/src/live`、`backend/internal/learning`；现有课程、资料、人工标准和评分继续复用。
- 当前 PostgreSQL 镜像为 `postgres:18.1-alpine3.23`；Redis/Asynq 已有，但 worker 尚未注册业务任务。
- 当前助手把资料整篇拼入上下文，按 16000 字节预算跳过放不下的资料，未实现片段检索。
- 当前资料支持文本和外链；尚无文件上传、解析、OCR、独立知识条目与向量索引。

## 3. 具体技术选型

| 层 | 工程默认 | 说明 |
| --- | --- | --- |
| RAG 实现 | Go 内实现明确的检索流程 | 延续 Gin、pgx/sqlc；不引入独立 RAG 平台、Agent 框架或另一套用户权限 |
| 向量存储 | PostgreSQL 18 + pgvector 0.8.7 | 沿当前 PostgreSQL 基座构建扩展镜像，保留数据路径与卷；记录扩展版本和镜像 digest |
| Go 向量驱动 | `pgvector-go` | 连接池注册向量类型，与 sqlc 类型映射配套；依赖版本在 Docker 编译验证后固定 |
| 向量检索 | 余弦距离、精确搜索起步 | 先验证课程规模的效果和延迟；有数据证明需要时再加 HNSW |
| 中文关键词 | Go `gse` 分词 + PostgreSQL `simple` 全文检索 + GIN | 同一分词版本处理文档和查询；课程术语、数字与英文标识符保留；排序用 PostgreSQL 原生排名，不称为 BM25 |
| 融合排序 | RRF | 两路召回合并、去重和出处聚合；首批不默认启用独立 reranker |
| 默认 Embedding | 百炼 `text-embedding-v4`，1024 维 | 模型与维度属于索引空间配置，不写死在所有第三方接口或整张向量表上 |
| 默认生成模型 | 百炼 `qwen-plus` | 知识提炼、归类解释、标准起草、问答与评阅草稿使用；模型可由服务端配置替换 |
| 文档工具 | Python 3.12，作为 Go worker 调用的本地工具 | 输入文件路径与选项，输出结构化 JSON；不新增独立 Python 业务 API |
| PDF 与表格 | `pdfplumber` 0.11.10 | 按页提取文本、表格和坐标；扫描页才渲染并 OCR |
| Office | `python-docx` 1.2.0、`python-pptx` 1.0.2 | 提取段落、列表、常规表格、幻灯片与图片位置；保留原件 |
| 文本和网页 | 文本/Markdown 按结构读取；HTML 使用 Beautiful Soup 4.15.0 | 网页索引基于获取的内容快照；仅保存链接不等于可全文检索 |
| 中文 OCR | RapidOCR 3.10.0 + ONNX Runtime CPU | 中文印刷体扫描为首批验证对象；模型文件离线打包并记录校验值，导入时不临时下载模型 |
| 异步处理 | 现有 Redis/Asynq + PostgreSQL 任务记录 | 数据库保存业务状态，队列负责执行；任务幂等、失败可定向重试 |
| 文件存储 | 本项目 Docker 持久化文件卷 | 原件、页图、解析结果分区；数据库保存元数据与定位；不先引入对象存储服务 |
| 前端 | 现有 React、TypeScript、Ant Design、React Query | 接真实接口，沿用身份、课程上下文、对象深链和编辑恢复 |

上述新增 Python 版本为已核对存在的安装候选。完整依赖锁定、CPU 兼容性、解析质量与内存峰值须经过构建及样例验证；未验证前不声称该组合已运行通过。

## 4. 模型配置和第三方兼容边界

### 4.1 配置方式

- 维护者提供服务端模型配置文件，多组 profile 分别声明 `id/display_name/kind/protocol/base_url/model/key_env`。
- Embedding profile 额外记录维度、单次输入上限、批量大小及已验证的可选参数；query/document 指令存在差异的模型由适配器明确处理。
- 浏览器仅取得可用模型 ID、名称、用途和状态，不取得密钥、私有认证头或可修改的任意请求地址。
- 同一课程/知识库绑定活动 Embedding 空间。教师可以请求切换配置，系统重建新空间，验证就绪后切换；不在每次问答中随意混用 Embedding。
- 教师可在已配置的生成模型中选择；每次运行记录实际请求模型、配置指纹、提示版本和时间。别名不冒充不可变模型版本。

### 4.2 首个百炼配置

- 默认兼容 Base URL：`https://dashscope.aliyuncs.com/compatible-mode/v1`。控制台若提供业务空间专属地址，则配置为该地址，不猜测空间 ID。
- 认证：服务端 Bearer API Key；使用北京按量 API 的有效凭据。
- 本地私密文件：`.local/model-secrets.env`，变量为 `DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL`。
- 当前没有取得新的可用密钥；创建的私密文件仅为空白模板，不沿用历史聊天密钥，不宣称接口已联调。
- 此私密文件当前尚未接入现有应用；接入代码和 Compose 环境加载属于后续实现。

### 4.3 兼容承诺

首批完成标准 OpenAI Embeddings 协议及百炼真实联调：支持服务器配置的地址、模型、认证与数值型单向量输出。不同厂商的批量限制、可选参数和响应细节通过受测 profile 或适配器处理。仅提供聊天接口的服务不能充当 Embedding 服务。

任意厂商的专有协议不承诺无修改即用；遇到非兼容协议，以公开文档或脱敏样例新增小型适配器，不做通用脚本执行或可编程工作流平台。稀疏向量、多向量及多模态 Embedding 不在本轮兼容验收内。

接入测试至少覆盖：单条/多条输入、响应 index 重排、条数与维度一致性、非有限值/零向量、超长输入、错误认证、限流、超时与错误响应。供应商变化不得静默改变已经使用的索引空间。

## 5. 导入、解析和引用细节

1. 教师在课程内上传文件或录入文本，保存原始字节、哈希、来源说明和私有来源版本；相同课程重复导入先提示，不泄露其他课程内容。
2. 解析任务逐文件处理。原件不覆盖；正文、目录、表格与异常信息进入解析快照。缺页、乱码、损坏、加密或无法访问的链接明确报告。
3. 正文正常的 PDF 不先 OCR；扫描页或人工指定页才执行 OCR。扫描表格的结构若不能可靠恢复，标记待核并展示页图，不伪造精确单元格。
4. 复杂公式、图表和手写内容保留原件/图片、位置与异常提示；首批不承诺自动理解其完整语义。
5. 可用片段可直接进入教师授权的原文索引；异常片段暂不进入正式检索，教师纠正后生成新解析修订。
6. 学习资料可选全文或部分章节编排发布。片段的学生访问范围通过实际发布绑定计算，不以“原文件部分内容已公开”推定整份公开。
7. PDF 定位保存页码与坐标；DOCX 保存段落/表格单元格位置；PPTX 保存幻灯片与形状位置；文本保存行号和字符区间。Office 不伪造固定页码。
8. 引文匹配基于冻结解析正文的 Unicode 字符区间，统一使用左闭右开区间；原始文件哈希与解析正文哈希分别保存。
9. 原文、教师补充和 AI 建议区分展示。Embedding 输入可带标题上下文，但最终引用必须定位到真实来源片段。

工程初始限制：单文件 30MiB、单批 10 个文件、单文件最多 200 页/张幻灯片；逐页处理，解析并发 1。应用实际文件限制与代理请求体上限分别配置，为 multipart 开销保留余量。超限应显式提示拆分，不静默截断。

这些是首批资源保护参数，按真实讲义样例和资源测量调整，不代表教学资料天然应该受这些上限限制。

## 6. 分块与检索的初始参数

### 6.1 分块

- 优先按标题、段落、列表、表格形成自然单元；不跨明显主题标题拼接。
- 普通正文初始目标约 800 个 Unicode 字符；超过约 1200 字符的长段按句子切分。英文/代码密集内容同时受模型 Token 上限约束。
- 只对连续长段切分保留约 80 字符重叠，不给所有独立段落强加重叠。
- 表格保留表头、相关说明与行关系；过大的表格按行组切分并重复必要表头，不截断单元格或丢掉单位。
- 适用条件、否定词和数字范围与结论关联；相邻父段落可在命中后补入上下文。
- 冻结 chunker 版本。正文/切块输入变化才更新相应向量；权限变化先更新访问控制，不重算全文向量。

### 6.2 向量化与融合

- 百炼 profile 首次每批最多 10 条，并发 1；每条包含明确可检索正文，不向模型发送整个文件二进制。
- 相同 Embedding 空间与相同输入哈希可以复用结果；跨空间不复用。
- SQL 在当前用户可访问、用途允许且空间一致的候选中执行检索；返回上下文前再次校验当前状态。
- 初始向量召回 20 条，关键词召回 20 条；RRF 常数 60，合并并去重。
- 默认最多选 6 个片段，连同必要父段落控制在约 4000 Token 的上下文预算内；不能为凑满数量加入明显无关内容。
- 先使用原文与确认知识两类内容共同检索；候选知识仅在授权的教师加工界面显式使用，不进入学生正式问答。
- 相关性不足、条件冲突或关键依据缺失时说明缺口；相似度不作为真假判定或掌握程度。
- 上述召回数量、分块参数和上下文预算是待评测初值，不宣传为最优值。不预设一个跨模型通用的相似度阈值。

## 7. 数据与任务边界

| 数据组 | 最小内容与责任 |
| --- | --- |
| 原始来源与解析 | 原件/来源版本、内容哈希、解析版本、片段正文、结构定位与质量状态 |
| 学习资料 | 复用 `resources` 历史与发布链；新增与来源片段的绑定，兼容已有纯文本资料及历史题目引用 |
| 精炼知识 | 稳定条目身份、不可变确认版本、适用条件、出处关联、知识点/关系、用途与可见性 |
| 检索索引 | chunk、实际来源区间、Embedding 空间、输入哈希、向量和建索引状态 |
| 业务加工任务 | 输入版本/哈希、任务类型、状态、进度、错误、重试与幂等键；模型输出草稿保留出处 |
| 模型调用记录 | 模型配置、请求用途、Token 用量、预估/已知成本、延迟和失败；密钥不落日志 |
| 题目与评分关联 | 复用题目、独立标准和评分修订；补充确认依据快照，不改写原始作答与已发布评分 |

- 向量表不把全部提供商固定为 1024 维。每条向量关联明确空间；空间标识含模型配置、维度和输入处理版本。
- 资料发布状态、知识确认状态、索引状态、任务执行状态分开维护。
- 任务先保存数据库状态再入队。入队失败可恢复补投；执行按版本/输入哈希幂等，不重复生成相同业务结果。
- worker 写回前检查任务输入是否过期。教师已编辑的内容不被迟到 AI 结果覆盖；新加工结果作为新候选供比较。
- 取消、超时和失败只清理本任务临时页图；原件、既有有效版本和历史证据保留。
- 来源错误/授权撤回与普通资料下架区分处理。前者限制受影响派生内容并列出关联对象；后者不无条件删除独立有效知识。
- 历史快照用于追溯，不能绕过当前访问限制；需要重评时新增修订，由教师确认发布。

## 8. 对外接口与前端工作区

接口采用现有会话、CSRF、课程归属和对象归属检查；下表是职责契约，具体路由在实施时保持现有命名风格。

| 接口职责 | 输入 | 输出/规则 |
| --- | --- | --- |
| 来源导入与修订 | 文件/文本/链接、课程、来源说明 | 来源版本、处理任务；不自动发布 |
| 来源/任务查询 | 已授权对象 ID | 原件预览、结构正文、定位、异常与进度；磁盘绝对路径不外露 |
| 资料编排与发布 | 来源片段选择、正文补充、范围 | 新资料版本与片段授权关系；沿用既有学习入口 |
| 知识加工与审核 | 来源范围、模型 profile、候选编辑 | 草稿、比较建议、出处和确认版本 |
| 搜索 | 查询、资料/知识范围、场景 | 命中内容、片段/版本/定位；权限由服务端确定，不能由客户端参数绕过 |
| 模型目录 | 当前用户/课程 | 已配置模型的安全元数据，无密钥 |
| 问答与标准起草 | 问题/题干、模型选择、授权对象 | 有引用的解释或待审草稿，记录实际使用证据 |
| 评阅草稿 | 原始提交、确认标准与依据快照 | AI草稿及检查结果；教师采纳/修改后进入既有评分确认发布链 |

前端收敛到四个工作区：资料导入/预览/发布；原文/候选/已有知识对照审核；搜索与全文阅读；题目评分依据及更新影响查看。

已有课程目录、阅读记录、笔记、人工标准与人工评分继续使用真实接口。模型或索引不可用时显示实际状态；不伪装成功、不回落到固定 AI 样例。

## 9. 目录与部署策略

- 现有 `learning` 保留身份/课程上下文及兼容入口；实现按业务职责增加 materials、knowledge、retrieval 和 model 的实际代码边界，不先重构整个旧模块。
- 解析脚本放在后端工具目录，由现有 Go worker 启动受限子进程并读取结构化结果；无独立对外端口。
- API 镜像保持精简；worker 增加专门 Docker target，安装 Python/解析/OCR依赖并带受校验的模型文件。需要时使用兼容 Python wheels 的 Debian slim 运行层。
- API 和 worker 共享本项目的来源文件卷；原件下载、页图和引用预览全部经过后端对象授权。
- PostgreSQL 扩展镜像保持当前主版本和卷挂载约定，不删除卷、不用新 PG 主版本读取旧数据目录。
- 本地按一条解析任务、一路 Embedding 起步；先测 OCR/解析内存。2GB 公网环境是否承载新增 worker 需实测，不能用本机 40GB 结果代替。
- 本轮先做本地 Docker 验收；生产需要可用 SSH、当前资源核实、备份恢复及镜像迁移验证，不由本文自动触发发布。

## 10. 50 元预算与运行控制

- 50 元是本项目本轮受控联调预算，不包含服务商账户中其他应用的调用。
- 首轮只用已批准课程资料和构造答案验证，不先导入真实学生隐私数据。
- 调用前按照当前地域/模型价格和最大请求量预留预算；并发任务共用预算记录，不各自计算余额。
- 记录调用用途、模型、输入/输出用量、预估和可获得的实际费用。价格未核对或无法保守估算时不自动开批量调用。
- 预留与已发生费用达到预算即停止启动新请求；失败重试也计入预留。超时后的计费不确定性保留记录，不当作免费自动重试。
- 初始生成并发 2、Embedding 并发 1；限流与短暂错误有界重试，认证/参数错误直接报告。
- 用户触发知识加工和标准起草，资料导入不自动触发全库生成式加工；OCR采用本地CPU，不增加云OCR费用。
- 百炼侧账单用于核对；不声称本地估算能限制服务商账户的全部支出。

权限越界、虚构出处、历史覆盖、未经确认发布为阻断项。语义检索质量先冻结样本并报告基线，再据实调整参数；不预写效果达标结论。原文定位成功不等于语义支持成立，语义仍需对照核查。

验证采用本项目有标签的独立测试课程；不清理公网演示数据。Docker构建串行、步骤可观察；变更后同步实际契约、架构入口和验证记录。
