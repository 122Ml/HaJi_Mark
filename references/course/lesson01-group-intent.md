1. 初选的选做模块

第一选择：E6 主观题智能评阅
第二选择：E4 重点难点发现

（说明：两者同一套底座——都建立在「学生答题数据 + 题目-知识点映射」之上，故第二选择只是应用面不同，
若 E6 因评分标准或样本量问题不成立，可直接降级到 E4，前期数据与日志工作不浪费。）


────────────────────────────────────────
2. 给谁用

一线任课教师，具体到「大班教学（100 人以上）、需批改简答/方案设计类主观题、没有助教可用」的教师。

（不使用模糊的"师生大家"。学生的反馈是教师审核后的下游产物，不作为第一使用者。不是学生自测工具。）


────────────────────────────────────────
3. 解决一个什么困难

主观题评分「同一份答案、不同时间或不同人给分不一样」，学生拿到分数却不知道差在哪——教师在大班
条件下既保不住评分一致性，也挤不出时间给出定位到具体句子的反馈。

（只保留「评分不一致 + 反馈不可定位」这一个困难的同一侧面，不塞评阅慢、作业抄袭、学习动力等其他痛点。）


────────────────────────────────────────
4. AI 内核一句话

用 LLM + RAG（检索课程材料与评分标准）+ 评分标准（rubric）分解，
凭 学生作答原文 + 评分标准要点 + 课程材料片段，
做 逐维度的证据匹配与得分判定（含错因归类与置信度估计），
给 维度分 + 引用学生原句的理由 + 针对性改进建议 + 低置信度转人工标记。

（不写"用 AI 分析答案"。四格逐项落点：技术=LLM+RAG+rubric 分解；依据=作答原文/标准要点/材料片段；
判断=每个维度是否命中、命中到什么程度、属于哪类错因；结果=分数+理由+证据句+人工复核队列。）


────────────────────────────────────────
5. 怎么证明它有效

标准答案：教师对同一批答案的评分（双评 + 分歧仲裁）。若数据不足，先合成 30–50 份「带已知缺陷类型
（漏要点 / 概念错 / 论证跳跃）」的作答，教师真评一遍当标准答案。

指标：与人工评分的一致性 QWK（二次加权 Kappa）为主指标；其次为逐维度一致性、MAE、同一答案重复
评分的方差；教师复核采纳率与平均修改幅度；「评分理由能否指到具体原句」的人工可用性评分。

基线：无 rubric 的整体打分（一次性 LLM 打分）、只给总分不给维度、按答案长度/关键词命中率的朴素规则。

（不写"效果会更好"。主指标是 QWK，基线是"去掉 rubric 结构的整体打分"，可比、可复现。）


────────────────────────────────────────
6. 怎么接进主线闭环

上游取数：从「干」环节取学生主观作答产出，从「学」环节取课程材料与题目，评分标准（rubric）由教师
在平台维护并版本化；知识点维度对齐「画」环节的知识图谱。

本环节：逐维度证据匹配 → 产出分数 + 理由 + 证据句 + 置信度。

下游交付：分数与置信度交「诊」环节，补上客观题测不出的表达能力/逻辑组织维度；教师审核后的反馈卡
片下发学生；低置信度样本进入人工复核队列，教师修正记录回写用于迭代评分器。

（写清数据从哪来、结果交给谁，不是一个孤立的打分工具。）


────────────────────────────────────────
7. 这次不做什么

① 不做多题型、多课程、全学科通用评分器——只做 1 门课的 1 类题型（简答或方案设计），rubric 维度不超过 3 个。
② 不做以总分自动定成绩：教师必须终审；低置信度一律转人工。也不做与 E4 重叠的班级共性分析（那是 E4）。
③ 不做作文文采评分、不做抄袭检测、不做答案自动生成或自动泄题。

8. 纵向分工

①【　　】主责「评阅内核（rubric 分解 + 逐维度判定）」｜横向「AI 与评测」：双评标准答案、QWK 指标、

③【　　】主责「教师复核与反馈界面（分数修改、理由编辑、低置信度队列）」｜横向「项目与需求」：对接
　课程组、维护需求与验收标准
④【　　】主责「批量评阅流水线与异常检测（超长、跑题、空答）」｜横向「质量与交付」：测试规范、CI、
　演示与文档，不替他人写测试

（每人一行：主责模块自己设计 + 写 + 测，端到端负责；横向四职责按「项目与需求 / AI 与评测 / 数据与接口 /
质量与交付」分配，不按前端后端 AI 分层。）
