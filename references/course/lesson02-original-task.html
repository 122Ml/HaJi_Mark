四人协作，但每人都要理解

建议一人组织场景与边界，一人操作AI并保存请求，一人核对结果与证据，一人整理图和下一步。中途互相解释，课后按第一课的模块纵向责任继续分工；课堂角色不意味着有人以后只写文档。

课堂最低完成线：一张带数据箭头的图、一条可查的AI审查、一项实际探查及其结果、一份明确责任和问题的启动初稿。时间不足时缩小样例范围并注明，不能用未来计划冒充已运行。

发给AI的任务请求模板

模糊请求

“帮我们设计最智能的学习平台，把所有功能实现。”

缺少用户场景、已有数据、范围、验证方式。AI可能建议大量组件，团队却无法判断哪些必要。

可核查请求

“我们探索AI助教能否根据下面四段资料回答并引用。先列输入输出、缺失信息与两种简化方案，再提出三个检查样例；不要生成整个平台。”

写清六项内容

  1. 目标：当前要解决或查明什么，而非最终所有功能。
  2. 上下文：用户场景、模块位置、实际可用的资料／数据。
  3. 输入输出：给出至少一个具体输入，说明希望看到什么。
  4. 边界：本次做什么、暂不做什么；可操作资源与禁止操作。
  5. 检查：如何判断可行，怎样保留失败。
  6. 不确定性：要求AI指出假设和缺失信息，避免擅自补全。
我们是软件工程智能学习平台第__组，初选__与__模块。
当前探索对象：__，位于__→__之间。
用户场景：__；已有数据：__。
本次输入：__；希望输出：__。
请先指出缺失信息，再提出两种最小方案和检查方法。
本次不做__，不得假设我们已有__。
请把“资料中明确给出”和“你的假设”分别标注。

上下文不是越多越好。只给当前判断所需材料；密钥、真实学生身份和无关资料不进入请求。页面样例均为教学构造数据。

技术探查不是提前完成整个功能

技术探查（spike）是为减少某个不确定性而进行的短期实验或原型。例如查明资料是否足够、输出结构能否满足接口、生成策略能否引用诊断证据。它应有明确问题、输入、操作和结果；展示AI能生成一段文字不够。

选择不确定性它会改变哪项决策？
→
固定小输入代表性与失败样例
→
预先写判据先定“怎样算符合”
→
实际操作保留原始输入输出
→
有限结论接受、修订、继续查
不够清楚可探查的问题可能改变的决策
能不能做AI助教？给定四段资料，模型能否引用存在且支持答案的来源，并拒绝资料外问题？增加引用核查、拒答规则；明确所需资料
诊断是否智能？同样模拟事件下，它会不会把证据不足的学生判为低掌握？引入“证据不足”状态与更多数据
干预建议好不好？建议是否包含具体资源、证据、教师审核与后续检查？改输出结构、保留审核环节

可以通过AI对话实际运行，或编写小脚本／原型。对话方式须保留材料、请求、工具／模型标识及原始输出；代码方式还保留源码与运行步骤。无需第二课完成服务部署。

工具不可用时：改做数据或资料可行性探查，例如知识点是否能找到对应资源、接口字段是否足够。记录实际检索／核对过程及缺口。它可以支持数据可用性判断，不能写成“模型效果已验证”。按同一探查方法与证据标准评价。

围绕本组模块开展一次探查

AI助教、诊断与教师干预三条路径都与平台闭环相连。选做其它模块的小组可使用后面的迁移表，仍需使用明确输入、判据与实际过程。

A：AI助教能否给出有依据的回答？

输入来自课件资源，回答服务学生；问答事件后续进入记录与诊断。检索增强生成（RAG）是先从资料中检索相关片段，再让模型依据片段生成。今天直接提供四段资料测试生成与依据，不把“全部资料放提示词”称为已经实现完整RAG。

资料编号本次给定文本（教学材料）
S1 · 课件第12页等价类划分把输入域分成若干类，同一类中的输入预期具有类似处理行为；从各类选择代表值。有效与无效等价类都需考虑。
S2 · 课件第13页边界值分析关注取值边缘附近。若允许整数年龄18到60，则可检查17、18、19、59、60、61。它与等价类划分互补。
S3 · 课件第14页单元测试检查局部逻辑单元，使用可控输入和预期结果；集成测试检查组件之间的协作和接口。
S4 · 课件第15页软件测试可暴露缺陷，但测试通过不能证明所有情形下没有缺陷。
固定输入预先判据
等价类划分与边界值分析有什么区别？区分类代表与边缘检查；引用S1、S2并支持解释。
年龄范围18—60，建议哪些边界输入？按给定资料列边界附近输入，不把17、61称为合法年龄；引用S2。
学校图书馆下周几点关门？说明材料不足；不编造时间或课程出处。

具体操作

  1. 用本任务单的请求模板请求最小方案，审查一个假设。
  2. 将四段资料与三题一次性给AI或逐题运行；保存完整实际输出。
  3. 按“关键内容、出处存在、出处支持、资料不足处理”逐题核对，写理由。
  4. 根据一个失败或风险修改提示／结构，再跑同样三题；未出现失败时新增一个资料外或含糊问题，避免只展示顺利样例。
  5. 说明改变、观察到的差异和局限；有修改不等于效果提升。

输出：方案及审查、两轮请求与原始结果、逐题核对、下一步。三个样例仅支持探查判断，不给全平台准确率结论。

B：诊断会不会把缺少证据误认为不会？

输入由测验与行为记录提供，诊断传给画像、推荐和教师看板。以下记录是构造的模拟资料；“模式”是本次核对依据，不是真实学生能力标签。

模拟学生给定记录本次可支持的观察
A边界值题1错、题2错，理由都把范围外值称为有效；等价类题正确；看完相关课件。存在边界有效性混淆迹象，应引用两次错误；不足以断言所有知识点掌握度。
B没有答题记录，只观看视频20秒；未给视频总长。证据不足；不能直接判低掌握或“不认真”。
C边界值题1正确、题2正确，理由包含上下界及范围外测试；其它知识点无数据。这些任务有正向证据；不能推出整体满分掌握。
要求每名学生输出：
student_id、observation、evidence、uncertainty、next_check。
只能使用给定记录，不补造答题或观看事件。
把“观察事实”与“可能解释”分开。
  1. 请求AI提出最小诊断方案，指出“观看少就不会”等未经证实假设。
  2. 同一规则下诊断A、B、C，保留原始输出。
  3. 核对证据引用、是否编造、是否把不足当低掌握、是否说明局限。
  4. 将A的一次错误理由删掉，再运行；观察不确定性是否合理变化。
  5. 用结果说明第三课需要哪些数据字段和行为约束。后续正式评测仍需独立基线与真值设计。

输出：方案审查、两批输入输出、逐项核对、数据缺口及下一步。不以模型自身的数字掌握度作为真值。

C：教师干预建议能否具体、有依据且可审核？

该扩展接在诊断与教师看板之后，由教师审核再下发；不自动修改学生成绩。

诊断D1（模拟）：学生A在两道边界题中把范围外值称为有效；
其它知识点证据不足。只建议检查边界有效性理解。
可用资源：R1＝课件第13页，边界值说明与年龄例子；
R2＝练习“整数分数0—100的边界测试值”；
R3＝课件第14页，单元／集成测试。
约束：仅从R1—R3选择；生成教师审核草案，不直接发送。
输出应含预先判据
目标与证据对应边界有效性混淆，并引用D1，不扩展成无据的心理／成绩判断。
具体步骤与资源使用R1／R2等实际存在资源，步骤可执行，说明选择理由。
后续检查用一个新的边界任务检查理解，而非写“提高效果”。
审核状态pending_teacher_review；不得宣称已发送或已改善成绩。
  1. AI提出策略结构；人工指出一个约束遗漏。
  2. 实际生成一份草案，逐项核对。
  3. 再输入“诊断证据不足，无明确错误类型”，观察是否仍生成确定性纠错方案。
  4. 按观察修订规则或任务，保留前后结果及局限。

输出：任务、候选审查、草案与证据不足场景结果、核对表、教师审核接口想法。
